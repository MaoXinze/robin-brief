# 01 · 项目概述

## 1.1 一句话介绍

**知更 Robin** 是一个多 Agent 协作的 AI 行业每日早报系统：每天自动从多渠道抓取 AI 资讯，由 9 个 Agent 组成的"编辑部"完成采集、提纯、撰写、出版，产出一份 60 秒可读完的早报页面并推送飞书。

## 1.2 命名故事

知更鸟（Robin）每天清晨报晓——正如这套系统里的 Agent 集群，每天清晨为你"报"来行业"更新"：

- **知** = 新知：每天值得知道的行业大事
- **更** = 更新：变化、动态、刚刚发生

品牌视觉也取自知更鸟：**蛋壳蓝**（刊头、快讯编号）+ **胸羽橙红**（微语、点评、星级）。

## 1.3 背景与痛点

| 痛点 | 现状 | 知更的解法 |
|---|---|---|
| 信息过载 | AI 领域每天产生数百条资讯，刷完要 30+ 分钟 | 流水线把数百条压缩成「5 头条 + 12 快讯 + 2 解读」 |
| 只有信息没有判断 | 聚合器只给标题链接，读者仍要自己判断重要性 | 每条头条附「为什么重要」点评；重大事件给深度解读 |
| 不敢信 | LLM 生成的新闻摘要可能幻觉 | 三道防线：基于原文生成 / 保留来源链接 / 评分理由透明 |
| 重复劳动 | 同一事件多家媒体报道，读者反复看到同一条 | 四层去重（URL/标题/模糊/历史库），临界情况 LLM 裁决 |
| 黑盒系统 | 生成过程不可见，出问题不知道在哪一环 | 运行报告记录完整漏斗与各 Agent 耗时/token |

## 1.4 产品哲学（四条主线）

1. **编辑部隐喻，不是爬虫聚合器**
   多 Agent 不是"多个函数换个名字"，而是一家 AI 原生编辑部的分工：采集记者负责找料、去重管理员负责合并同事件、分类编辑与评分编辑负责筛选排序、摘要主笔与头条编辑负责写作、深度评论员负责观点、出版发行负责交付。日报的价值标准只有一句话：**只读这 60 秒，不错过今天 AI 世界最重要的事。**

2. **可信度优先**
   LLM 新闻产品的最大风险是幻觉。三道防线：
   - 摘要/点评必须基于抓取到的原文生成（Prompt 中明确禁止编造数字与事实）
   - 每条新闻保留来源名称与原文链接，读者可随时回溯
   - 重要性评分展示理由，且由可解释的规则引擎主导、LLM 只做 ±1 星校准

3. **「为什么重要」比「发生了什么」更有价值**
   这是人工编辑日报相对聚合器的核心壁垒，也是本项目的核心 LLM 应用点。

4. **可观测、可评测、可演进**
   - 可观测：`run_report.json` 记录漏斗（采集 N → 去重 M → 入报 K）、每个 Agent 的耗时、每次 LLM 调用的 token 用量
   - 可评测：分类/评分规则是确定性的，可构建标注集持续评测（Roadmap）
   - 可演进：内容生产与呈现分离，分发层可插拔（Roadmap 中的多渠道推送）

## 1.5 功能清单（v1）

**核心流水线**
- [x] 6 类数据源适配器：RSS 通用 / Hacker News API / arXiv API / GitHub Trending 页面解析
- [x] LangGraph 状态图编排：Send 动态并行采集、条件边宽松重采、checkpoint
- [x] 四层去重：URL 精确 → 标题归一 → 模糊聚类 → 近 3 天历史库，临界对 LLM 裁决
- [x] LLM 分类打标（7 类）+ 非相关内容自动丢弃
- [x] 规则引擎评分（公司权重 × 事件类型 × 时效 × 热度）+ LLM 校准，附评分理由
- [x] 一句话摘要（严格基于原文）
- [x] 头条编辑：选 3~5 条 + 「为什么重要」点评 + 今日微语
- [x] 深度解读：1~2 个重大事件的「背景 + 影响」
- [x] 晨光纸感版早报渲染（HTML 移动端优先 + Markdown）
- [x] SQLite 归档（文章库 / 日报 / 运行记录）+ 昨日回顾（连续阅读感）
- [x] 飞书自定义机器人推送（交互卡片 + 加签）
- [x] 运行报告（漏斗 / 耗时 / token / 来源错误）

**工程质量**
- [x] 33 个 pytest 测试（含端到端全链路），全部离线可复现

- [x] 错误隔离：单源失败不影响整体，错误进运行报告
- [x] typer CLI：`robin run / demo / schedule / archive / init`
- [x] Dockerfile

## 1.7 与参考方案的差异（自主设计部分）

本项目参考了公开的多 Agent 日报方案与两份视觉参考（深色科技风日报、报纸风"每日60秒"），但在以下方面是自主设计决策：

1. **视觉**：没有照搬任何一份参考图，而是选择「晨光纸感」浅色报纸风——理由：深色 AI 面板缺乏辨识度；晨间读报场景适合浅色；手机/打印友好；知更鸟品牌色独有
2. **去重方案**：参考方案用"向量数据库语义去重"，实测发现默认 LLM 供应商（DeepSeek）无 embeddings 端点，改为「规则 + 模糊聚类 + LLM 裁决」三层方案，零额外依赖（embedding 方案保留在 Roadmap）
3. **评分设计**：规则引擎主导（可解释、零成本、可测试），LLM 只做校准——而不是全程 LLM 打分
4. **快讯复用摘要**：快讯不重复调用 LLM，直接复用摘要主笔的产物，省 token 且口径一致
5. **昨日回顾**：从归档库取昨日头条，形成连续阅读感——参考方案没有的细节
6. **工程化深度**：33 个测试、运行报告、mock 全链路、错误隔离——参考方案只到 Demo 层
