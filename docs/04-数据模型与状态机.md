# 04 · 数据模型与状态机

## 4.1 实体模型（`models.py`，pydantic v2）

```
Article                    采集层原始条目
 ├─ id                     规范化 URL 的 sha1 前 16 位（全局唯一、稳定）
 ├─ source_id / source_name / source_weight
 ├─ url / title / content / author
 ├─ published_at / fetched_at (aware UTC)
 └─ points                 社区热度（HN points / GitHub stars），可空

EnrichedArticle(Article)   智能层逐步叠加字段的不可变产物
 ├─ category               七类枚举
 ├─ companies[]            涉及公司
 ├─ importance             1~5 星（0=未评分）
 ├─ score_reason           评分理由（随日报展示）
 ├─ summary                一句话摘要
 └─ is_ai                  分类编辑判定，false 即丢弃

BriefDocument              结构化日报（渲染层唯一输入）
 ├─ run_date / weekday_cn / lunar_str / agent_count
 ├─ epigraph               今日微语
 ├─ headlines[]            HeadlineView（含 comment 点评）
 ├─ quick_news[]           QuickNewsView
 ├─ analysis[]             AnalysisView（背景+影响）
 ├─ yesterday              YesterdayView（昨日回顾）
 ├─ sources_used / funnel / generated_at / is_demo

RunReport                  运行报告
 ├─ funnel / agent_stats / source_errors / llm_usage / output_files / status
```

**设计要点**：每个阶段产出**新实例**（`model_copy(update=...)`），字段逐步叠加、不可变、可追溯；`BriefDocument` 是渲染层唯一输入，Agent 产物与 HTML 版式完全解耦。

## 4.2 LangGraph 状态（`state.py`，TypedDict + reducer）

```python
class BriefState(TypedDict, total=False):
    # 运行上下文
    run_date / sources / now / window_hours / relaxed_window_hours
    relaxed / retry_count / push / mock
    history_norms: list[str]      # 近 3 天标题归一（跨天去重）
    yesterday: dict | None        # 昨日回顾

    # 采集（Send 并行 → reducer 汇聚）
    articles:  Annotated[list[Article], operator.add]
    source_errors: Annotated[list[dict], operator.add]
    source_stats: Annotated[dict, merge_dict]

    # 提纯与智能层
    deduped / dedup_stats / classified / scored / summarized

    # 编辑层（并行节点各自写不同键）
    headlines / quick_news / analysis / epigraph

    # 出版
    brief: BriefDocument / published
    stage_done: Annotated[dict, merge_dict]   # publish 幂等守卫
    agent_stats: Annotated[dict, merge_dict]  # 各节点耗时
```

**reducer 语义**：带 `Annotated` 的键在多路写入时自动合并（`operator.add` 拼列表、`merge_dict` 按键覆盖）；不带 reducer 的键后写覆盖。并行节点的输出只能写到"自己独有的键"，这是并行安全的关键约束。

## 4.3 图拓扑与条件边

```
START ──(条件边: dispatch_collect 返回 Send×N)──► fetch_source ×N   [并行]
                                                     │
                                                  dedup ◄─── 漏斗统计
                              ┌── 条件边: _route_after_dedup ──┐
                           [deduped < min_articles 且未宽松过]  [充足]
                              │                              │
                           relax ──(条件边: 再次 Send fan-out)  │
                                                              │
                                                          classify
                                                              │
                                                            score
                                                              │
                                                         summarize
                                                          ┌────┴────┐
                                                       editor    analyst   [并行]
                                                          │
                                                      quicknews
                                                          └────┬────┘
                                                             publish（幂等守卫）
                                                               │
                                                              END
```

**条件边 1（fan-out）**：`dispatch_collect` 读 state 里的源列表，返回 `Send("fetch_source", payload)` × N —— 源数量动态，并行执行，`operator.add` 汇聚。

**条件边 2（宽松重采循环）**：`_route_after_dedup` 返回 `"relax"` 或 `"continue"`。条数不足时 relax 节点放宽窗口/阈值并回到 fan-out —— 图中唯一的环，`relaxed` 标志 + `retry_count` 保证至多一次，`recursion_limit` 兜底。

**并行语义的实战细节**：editor 与 analyst 并行（写不同键，互不依赖）；quicknews 必须读 editor 的头条结果做排除，**同一超步内并行节点读不到彼此输出**，因此 quicknews 串在 editor 之后。publish 有多条入边，LangGraph 可能多次触发 —— 用 `stage_done` 完成标志做幂等守卫（见 08-开发日志 §5）。

## 4.4 容错与降级矩阵

| 故障 | 表现 | 恢复策略 |
|---|---|---|
| 单数据源超时/404 | source_errors 记一条 | 其他源照常；报告可见；漏斗含失败源计数 0 |
| 全部源失败 | 漏斗 collected=0 | 仍出版空报（degraded 状态），日志告警 |
| LLM 输出 JSON 不合法 | 自动重试（带错误回示），≤3 次 | 耗尽后走节点降级（分类→other、评分→规则分、摘要→标题截断、头条→评分直选） |
| 采集条数不足 | 触发宽松重采一次 | 仍不足则按现有条数出报 |
| 头条 < 3 条 | editor 降级补齐 | 按评分直选，保证报纸形态 |
| publish 被多次触发 | stage_done 守卫 | 仅一次真正出版，防重复推送 |
| 进程中断 | checkpoint 落盘 | 真实运行可从最近超步恢复（AsyncSqliteSaver） |

## 4.5 SQLite 表结构（`store/db.py`）

```sql
articles(run_date, id, source_id, source_name, url, title,
         title_norm, category, importance, summary,   -- PK(run_date,id)
         INDEX(run_date))          -- 文章库：跨天去重 / 归档
briefs(date PK, epigraph, html_path, md_path,
       headlines_json, funnel_json, created_at)    -- 日报归档：昨日回顾 / archive 命令
runs(id PK, run_date, started_at, finished_at, duration_s,
     mock, status, report_json)                    -- 运行记录：报告落库
```

连接参数 `check_same_thread=False` + 写锁：LangGraph 可能把同步节点放进线程池执行，SQLite 默认禁止跨线程使用（这是实测踩过的坑，见 08-开发日志 §6）。

## 4.6 可观测性设计

- **漏斗**：`collected → after_url → after_title → after_fuzzy → after_history → kept → classified → scored → headlines/quick_news/analysis`，任何环节的异常损耗都能定位
- **耗时**：图节点由 `_timed` 包装，每个 Agent 的 duration 写入 `agent_stats`
- **token**：`UsageTracker` 累计每次 LLM 调用的 prompt/completion tokens（mock 按字符估算，结构一致）
- **落点**：`run_report.json`（每日期目录）+ `runs` 表（长期可查）
