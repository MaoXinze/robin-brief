# 07 · Roadmap

> v1 已交付核心闭环（采集→出版→推送 + 全套测试与文档）。以下按价值/成本比排序，每项写清动机与预估工作量，体现产品演进思维。

## P1 · 短期（1~2 周可完成）

### 1. 评测集与质量回归 ⭐ 推荐 first
- **动机**：目前分类/评分质量只能人工抽查；建立 50~100 条人工标注集后，分类准确率、评分误差可量化，Prompt 调优有回归底线——从"能用"到"可信"的关键一步
- **方案**：标注数据存 `tests/eval/golden.jsonl`；`robin eval` 命令跑当前 Prompt/模型输出与标注对比，输出准确率报告
- **工作量**：2~3 天（大头在标注）

### 2. GitHub Actions 每日定时
- **动机**：免服务器日更；运行报告与日报自动提交回仓库，形成公开的"出版历史"
- **方案**：`.github/workflows/daily.yml`：cron（`30 0 * * *` UTC = 东八区 08:30）→ `robin run` → commit `output/` 回 main（注意 API Key 用 repo secrets）
- **工作量**：半天

### 3. FastAPI 历史归档站
- **动机**：让日报可以被"订阅"而非只能翻文件；也是 App/小程序等外部渠道的接入点（内容生产与分发分离的直接收益）
- **方案**：`GET /briefs/today`、`GET /briefs?date=&category=`、`GET /briefs/{date}/render`；数据全部来自 SQLite 现成表
- **工作量**：1~2 天

## P2 · 中期

### 4. 长图导出（报纸风分享）
- **动机**：「知更早报」是移动端长页，导出长图才能进朋友圈/微信群传播
- **方案**：Playwright headless 截图（本机 Edge headless 已验证可行，Playwright 仅为打包成依赖）；`robin export --png`
- **工作量**：1 天

### 5. 更多推送渠道
- **动机**：分发层可插拔是既定架构，加渠道边际成本极低
- **清单**：企业微信机器人 / QQ 机器人（NapCat 等）/ 邮件 SMTP / Telegram Bot
- **工作量**：每渠道 0.5 天

### 6. embedding 语义去重
- **动机**：模糊+LLM 裁决的漏斗在"改写幅度极大的洗稿"场景有漏；接入 embeddings 供应商后可加"语义向量层"
- **方案**：SQLite 存向量（blob），cosine 预筛 + LLM 确认；注意与现有四层漏斗的串联顺序
- **工作量**：2 天

### 7. ECharts 数据版块
- **动机**：「本周融资图谱」「模型发布时间线」等可视化提升日报信息密度
- **方案**：周一自动生成周报版块；图表数据由聚合 SQL 产出
- **工作量**：3~4 天

## P3 · 远期（产品化方向）

### 8. 个性化订阅
- 用户选择关注子领域（大模型/芯片/Agent/政策），分类标签体系已就绪，过滤发生在 Editor 之前
- 需要用户体系 → 与 FastAPI 归档站合并考虑

### 9. 互动问答（RAG）
- 日报底部"今日 AI 问答"：读者对头条事件提问，Agent 基于当日原文语料回答
- 原文都在 SQLite，向量化后即是现成 RAG 语料；注意答案必须带原文引用（延续可信度优先）

### 10. 双语输出
- 同一份 BriefDocument 渲染中英两版（翻译发生在摘要层，一次调用两语言输出）
- 面向海外读者/英文简历展示

### 11. Web 管理台
- 源管理、Prompt 在线调优、运行历史可视化、人工审核后发布（LangGraph interrupt 的人工介入点）

## 明确不做（负空间）

- **不做通用新闻聚合**：只做 AI 垂域，深度换广度是产品定位
- **不做自己的爬虫框架**：源适配器接口已是最小抽象，规模到 50+ 源再考虑
- **不做实时推送**：日报的价值在"编辑过的确定性"，实时是另一个产品
